# 通知与消息中心需求（已确认）

状态：需求已确认，开发暂停，等待用户恢复后再继续实现与联调。

## 1. 功能范围

- 所有已登录账号都显示“消息”入口。
- 消息中心展示三类互动通知：其他账号点赞了当前账号发布的帖子、评论了当前账号发布的帖子、回复了当前账号发布的评论。
- 当前不做点赞评论通知聚合；后续可在通知量变大时再扩展为“用户1、用户2等多人点赞”。
- 不通知自己的操作；取消点赞不产生通知。
- 页面操作成功提示与消息中心通知分离：操作提示只反馈给当前操作者，不写入消息中心。

## 2. 通知生成规则

- 点赞帖子成功后，通知帖子作者。
- 发布顶级评论成功后，通知帖子作者。
- 发布回复成功后，通知被回复评论的作者。
- 同一个业务事件只生成一条通知，重复投递不能产生重复记录。
- 通知内容保存文本快照；昵称不保存快照，展示时读取账号当前昵称。
- 用户不能修改昵称，因此不需要处理昵称变更历史。

## 3. 技术职责

```text
点赞/评论成功
    -> RabbitMQ 通知事件队列
    -> 消费者异步写入 MySQL 通知表
    -> Redis 未读数加一
```

- RabbitMQ：传递点赞、评论、回复事件；消费失败时允许重试，重复事件通过 `event_id` 幂等。
- MySQL：保存完整通知历史，作为消息中心的持久化来源。
- Redis：保存 `notification:unread:{accountId}` 未读数量，用于首页角标和快速查询。
- 不引入 WebSocket；首页每 10～15 秒轮询未读数量，消息中心打开时立即刷新。
- 不引入新的技术栈。

## 4. 消息中心交互

- 首页账号区域显示“消息”按钮和未读角标，超过 99 显示 `99+`。
- 支持“全部”和“未读”筛选。
- 分页展示，每页 20 条。
- 打开消息中心时刷新列表和未读数。
- 支持标记单条已读、全部标记已读。
- 支持删除单条通知，以及清空已读通知。
- 删除未读通知时，Redis 未读数同步减一；删除已读通知不改变未读数。
- 只有通知接收者本人可以查看、标记已读或删除通知。
- 暂不需要 `read_at`/已读时间字段，使用 `is_read` 布尔字段。

## 5. 跳转与删除后的展示

- 评论或回复通知点击后跳转到 `/post/{postId}?commentId={commentId}` 并定位评论。
- 帖子已删除：通知历史保留，显示“相关帖子已删除”，点击进入墓碑页。
- 评论已删除：通知历史保留，显示“相关评论已删除”，不再定位不存在的评论。
- 通知不因帖子或评论删除而级联删除。

## 6. 数据模型

通知表使用 `db_notification`，字段如下：

```text
id
recipient_id
actor_id
type                  # POST_LIKE / POST_COMMENT / COMMENT_REPLY
post_id
comment_id
content
created_at
is_read
event_id              # 唯一，用于事件幂等
```

- 通知保留 90 天，定时清理过期记录。
- 清理任务由 Java 后端定时任务执行。
