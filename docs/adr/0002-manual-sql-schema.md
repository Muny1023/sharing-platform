# 使用仓库 SQL 脚本手动维护数据库结构

项目当前使用手动维护的 MySQL 数据库。资源分享社区 MVP 采用可审查、可重复执行的 SQL 脚本记录表结构变更，由开发者手动执行，而不是在应用启动时自动建表或引入 Flyway。

## 为什么

- 现有数据库已经由手工 SQL 管理，直接引入迁移框架会增加初始化和基线迁移成本。
- SQL 文件进入版本控制后，表结构变更有明确记录，便于审查、回滚和在不同环境重建。
- 应用启动不应隐式修改数据库结构。

## 后果

- 每次表结构变更都必须同步更新仓库中的 SQL 脚本，并由开发者手动执行。
- 部署或换环境时，需要明确执行尚未应用的 SQL。
