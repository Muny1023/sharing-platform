# 我的发布、我的收藏、搜索与帖子软删除设计

社区 MVP 在现有“帖子/评论/点赞”之外扩展三类个人化能力：账号管理自己发布的帖子、收藏帖子以便之后找回、按关键词搜索帖子或评论。本 ADR 记录已经过问答确认的设计决策，作为后续接口与页面实现的依据。

## 决策

- “我的发布”和“我的收藏”是两个独立页面，从昵称/头像展开的隐藏入口进入，平时不直接暴露在首页导航；推荐路由为 `/my/posts`、`/my/favorites`。
- 收藏是账号对帖子的唯一标记，同一账号对同一帖子最多一条；收藏仅自己可见，不公开收藏人数，其他帖子流不展示收藏数。
- 收藏入口放在帖子详情页；“我的收藏”页面支持取消收藏。
- “我的发布”列表支持“最新 / 最热 / 最早”三种排序，与首页语义一致。
- “我的收藏”排序：最新按收藏时间倒序、最热按帖子点赞数倒序、最早按帖子发布时间正序。
- 作者可以编辑或删除自己的帖子。编辑使用独立编辑页，保存后返回帖子详情；编辑只改标题、正文、资源链接，保留原有评论、点赞和收藏。
- 删除采用物理删除：帖子正文、评论和点赞立即删除；收藏关系保留为失效收藏，并在保留期内通过统一墓碑页展示。
- 收藏列表中的已删除帖子显示灰色占位项，点击进入统一墓碑页，并保留“取消收藏”操作。
- 墓碑页不保留原帖标题、正文、资源链接或评论，只说明“该帖子已被作者删除”并提供返回首页入口。
- 搜索分两种模式：帖子搜索匹配标题和正文；评论搜索匹配评论内容，每条命中评论单独成行并带所属帖子标题，点击进入帖子详情定位到该评论。
- 搜索状态保留在 URL 中，刷新和返回页面不会丢失；搜索入口放在帖子流顶部，结果复用现有分页结构。
- 本轮不实现收藏标签/分类，也不为标签建表；后端收藏查询保留可扩展的分页查询对象，方便以后追加标签等过滤条件。
- 发帖增加账号维度防护：同一账号 30 秒最多发布一帖，每天最多 50 帖，限制状态存 Redis，不新增表。

## 为什么

- 收藏更像个人书签，公开收藏数会引入新的公开信号和帖子计数维护；本轮按私有实现更简单、语义更清晰。
- “我的发布”和“我的收藏”后续都会增加管理和筛选能力，独立页面比同一页面塞多个页签更利于扩展。
- 软删除是支撑统一墓碑页和“收藏中仍能看到已删除帖子”的最小实现：如果物理删除，收藏外键会级联消失，收藏列表不可能再展示已失效项。
- 标签形态尚未确定，提前建表或做筛选器会造成返工；先保留查询扩展位，不提前引入抽象。

## 范围边界

- 收藏只针对帖子，不收藏评论。
- 不做公开收藏数、不做标签、不做批量管理。
- 不做回收站或恢复入口。
- 墓碑和失效收藏保留 1 天，过期后自动清理；帖子本体删除时立即释放空间。

## 后果

- `db_post` 需要增加删除标记字段，`db_favorite` 需要新表，按 ADR 0002 的做法同步维护 SQL 脚本。
- 帖子详情、帖子流、搜索、我的发布和我的收藏的查询条件需要统一处理软删除标记。
- 现有 ADR 0001 中“允许编辑自己的帖子”从设计状态变为本 ADR 已确认的实现范围。
- 具体接口、请求/响应结构和前端页面结构将在后续实现轮次中确定，不在本 ADR 中锁死。
